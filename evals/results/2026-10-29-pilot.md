- **Agent and model:** Claude Code 2.1.312, headless (`claude -p`), Opus 5.5
- **Skill version:** `9cb2506`
- **Runs:** 1 per case and condition (pilot; see "Limits")

## Findings

1. **Write mode did not trigger.** For a plain "add a function" request, the agent did not load the skill. Write mode cannot help until the description triggers it, or the project's agent instructions name it. Next: the trigger test (prompts that should and should not load the skill) and a description change.
2. **Rule 5 gap in apply mode.** The agent treated "apply all the optimizations you recommend" as approval for items that change behavior, because the report listed them as risks rather than under "Behavior changes for review." The skill should say that a blanket request to apply never approves a behavior change: such items must be in "Behavior changes for review" before applying, and need a separate, item-by-item approval.
3. **Where the skill helped (ts-shop):** the four baseline fails are each a trap the skill's rules name: the `__proto__` key trap, deliberate bug fixing, silently removed stack overflow (plus a new crash on negative input), and snapshotting mutable entries.
4. **Cost:** the skill run cost about 5 times the baseline ($4.11 against $0.78), mostly differential tests and benchmarks in apply mode.

## Limits

One run per condition. Agents vary between runs, so these results show direction, not a reliable size of effect. The harness works, and the next round should use at least 3 runs per condition.
