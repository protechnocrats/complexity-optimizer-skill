## Harness problem found and fixed

The first three-run trigger test hit the account's 5-hour usage limit partway through. 26 sessions ended at once with HTTP 429 (`usage_limit_reached`) and did nothing, and the summary counted the 24 trivial ones as correct "skip" decisions, reporting 59 of 60. `trigger-test.sh` now reports errored sessions separately and does not score them, and `run-pilot.sh` logs "API ERROR, session invalid" in `progress.log` when a turn ends on an API error. N1–N8 were rerun after the limit reset.

## Findings

1. **Rule 5 fix confirmed.** No skill run applied a behavior change on "apply all" (round 1: it did). The baselines applied 3 to 5 silent behavior changes each.
2. **Write-mode triggering is the weakest point.** W1 loads in about 2 of 3 runs. A miss has a real cost: the TW1 run without the skill changed `PriceBook` without asking. Next: test whether the `CLAUDE.md` line from the README brings W1 to 3 of 3.
3. **Rule 4 or rule 5 for a crash?** Skill run 2 read the `packsNeeded` stack overflow as "an exception callers may catch" (rule 4, last paragraph) and held the whole fix for review, so the exponential code stayed. Runs 1 and 3 treated it as a bug removed as a side effect. Clarify in `SKILL.md` that a crash from resource exhaustion (stack overflow, out of memory) on valid input is a bug, not a contract. **Done after this round:** rule 4 in `SKILL.md` now says so.
4. **T12 answer key.** The key says the fix "cannot live in the caller" because `entries` is private. All three skill runs found an equivalent fix that needs no approval: a new public method that builds a lookup once per `monthlyStatements` call. The key should accept it as a pass and say whether adding a public method counts as changing the public surface. **Done after this round:** the T12 key accepts the per-call index and says that adding a method keeps the public contract, as long as the report names it.
5. **TW1 sizing.** One skill run said the repository gives no sizes, although `volumes.ts` does. `WRITING-NEW-CODE.md`, step 2, could name volume and configuration files explicitly.
6. **T11 bonus missed by everyone.** All six runs read `store.movements` even with an empty catalog. The bonus is probably too obscure to tell runs apart.
7. **Cost.** The skill costs about 3.2 times the baseline on ts-shop ($3.26 against $1.01 per session); round 1 was 5 times.

## Limits

Three runs per condition, one agent, one model, one fixture for apply mode. Kotlin, C, and Rust fixtures were not run this round. Swift was not run, because no Swift toolchain is installed here.
